## 填写指南

1. **背景与问题**：必须说清楚"为什么要做这个决策"，不要假设读者了解背景
2. **候选方案**：至少2个方案，必须有真实的对比分析，不要只写最终方案
3. **决策理由**：必须基于决策驱动因素和约束条件，有理有据
4. **预期后果**：必须诚实写出trade-off，不要只写好处
5. **验证与监控**：必须有可衡量的指标，不要写"持续观察"这种空话
6. **决策状态**：随时间更新，记录决策的演进过程

---

## ADR最佳实践

1. **一个决策一个文档**：不要在一个ADR里混杂多个决策
2. **不可变原则**：决策被接受后，不要修改原有内容，而是创建新的ADR并标记为"Superseded"
3. **链接相关决策**：构建决策网络，便于理解决策的上下文
4. **保留被拒绝的方案**：帮助未来的人理解"为什么不选XX"
5. **持续更新状态**：从Proposed → Accepted → Deprecated → Superseded

---

## 与五层结构模板的区别

| 维度     | 架构决策记录       | 五层结构模板       |
| -------- | ------------------ | ------------------ |
| 核心目标 | 记录决策过程与理由 | 提炼可复用知识     |
| 重点章节 | 候选方案、权衡分析 | 归因分析、底层逻辑 |
| 时效性   | 决策会过时、被取代 | 通用知识相对稳定   |
| 典型内容 | 技术选型、架构设计 | 思维模型、工作方法 |
