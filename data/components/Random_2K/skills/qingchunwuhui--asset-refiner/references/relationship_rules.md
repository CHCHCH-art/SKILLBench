# 关系识别详细规则

## 判断规则表

| 资产组合 | 关系特征 | 处理策略 |
|---------|---------|---------|
| **模型 + 工具** | 工具是模型的实现代码（如：Prompt、脚本） | ✅ **合并**（工具作为"03怎么解决"子章节） |
| **概念 + 案例** | 案例是概念的应用实例 | ✅ **合并**（案例作为"适用场景"或示例） |
| **通用模型 + 领域实现** | 同一模型在不同领域的变体（如：通用日志规范 vs Python日志规范） | ⚠️ **分离但强链接**（主卡片 + 派生卡片） |
| **SOP + SOP** | 解决不同问题的流程 | ❌ **分离**（独立建卡） |
| **Prompt + Prompt** | 服务不同场景的工具 | ❌ **分离**（独立建卡） |

---

## 自动判断逻辑

**当识别到 `[Level S 模型] + [Level A 工具]` 时，检查以下条件：**

1. [ ] **工具描述中是否包含"基于XX模型"、"实现XX模型"的字眼？**
2. [ ] **模型是否缺少"How"（具体操作步骤/代码）？**
3. [ ] **工具是否缺少"Why"（理论依据/使用场景）？**

**如果3个条件都满足 → 建议合并**

---

## 示例判断

```
资产1: "新技术学习价值评估四维模型" (Level S)
- 有 What/Why: ✅ 定义了相关性/时效性/成本/替代性
- 缺 How: ❌ 只有理论，没有可执行工具

资产2: "AI新工具学习决策助手Prompt" (Level A)
- 有 How: ✅ 完整的Prompt代码
- 缺 Why: ❌ 没有解释为什么这样评估
- 描述: "基于新技术价值评估模型"

判断: ✅ 符合合并条件（资产2是资产1的工具实现）
```
